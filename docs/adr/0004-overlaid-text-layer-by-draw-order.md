# ADR 0004 — 疊印文字層靠落筆次序分層，唔靠座標

日期：2026-09-11
狀態：已接受（追認 2026-08-31 起的實作）

## 背景

永明彩虹的便覽每一版都把另外一至兩版成版疊印上去：標題、截至日期、成張十大
持倉逐版重覆一次，而且疊上去嗰啲有幾版係上兩季的舊數（2025-09-30、2025-03-31）。
兩層之間只差兩至七 pt，有幾行兩份的百分比左界完全一樣。

即係話**座標分唔開兩層**。原本的防線 `rejectOverlaidRows` 做到「一行帶兩個
百分比就整塊當抽唔到」，結果 19 隻成分基金全部冇十大持倉——安全，但等於捨棄
一批真實存在的官方披露。

## 決定

**靠落筆次序分層。**

1. `pdftohtml -xml` 依內容流輸出，而內容流一定係先寫本頁自己嗰版。
   `PdfTextItem.drawIndex` 保住這個次序。
2. `TitleSelector.overlaidPages` 每頁取**最先落筆**嗰個標題，並且只讀到下一個
   標題落筆為止。
3. `rejectOverlaidRows` 保留做防線：切唔乾淨就會有一行帶兩個百分比，嗰陣
   寧可整塊當抽唔到，都唔靠座標猜邊個數值屬邊隻基金。

## 否決方案

- **靠座標分群。** 兩層有幾行的左界完全相同，數學上分唔開。
- **靠日期文字揀最新嗰層。** 疊印嗰啲「通常」係舊期，但冇任何保證；用內容
  倒推來源等於假設一個冇人保證嘅規律，而且一旦錯就係把另一季的持倉貼落去。
- **維持整塊當抽唔到。** 19 隻成分基金全部冇持倉，而披露其實喺度。

## 後果

- 實測 27 版全部第一層都係 `As at 30/06/2026`，19 隻成分基金全部齊十大持倉，
  並經逐頁對版核對。
- 抽取層依賴 `pdftohtml` 的內容流次序。**換 PDF 抽取工具要重新驗證這個前提**，
  唔可以當成通用事實。
- `rejectOverlaidRows` 唔可以因為「而家用落筆次序」而移走；佢係切唔乾淨時
  唯一一道防線。

## 重審條件

- 換走 `pdftohtml`（例如轉用其他 PDF 文字層抽取器）。
- 出現一份內容流次序唔係先寫本頁版本的便覽——嗰陣要改成逐份聲明，而唔係
  放寬規則。
