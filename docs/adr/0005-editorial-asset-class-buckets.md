# ADR 0005 — 第一版只做股票／債券／現金及其他三桶

日期：2026-09-11
狀態：已接受（#211 選項 A）

## 背景

便覽的配置表要跨計劃比較，但標籤本身唔統一：有純資產（`Equities`）、
資產 × 地區（`香港股票`）、純地區（`North America`）、純行業
（`Financials`）、評級（`AAA`）、貨幣（`USD`），同一張表仲會混住幾種維度。
原文照錄可以逐個計劃顯示，但做唔到「同組基金平均股票比重」這一類比較。

#211 列出三個選項：只做資產三桶（A）、資產加地區（B）、資產加地區加行業（C）。

## 決定

**第一版只做 A：股票／債券／現金及其他三桶。地區與行業暫緩。**

1. 對照表 `data/reference/allocation-label-map.json`，鍵是正規化後的標籤，
   值是 `equity` / `bond` / `cash_and_other` / `not_asset_class`。
2. 一張表的每一行都要映射到三桶、合計絕對值在 80 至 120 之間，先可以出三桶。
   資產 × 地區可加總。
3. 純地區、純行業、評級、貨幣，或同一張表混咗這些，走
   `mappedAllocation.unavailable`，原因 `not-asset-class`。
4. 結果寫在 payload 的 `mappedAllocation`，`official: false`，
   顯示時必須標明「編輯歸類，非官方分類」。原文表仍然留喺 `factSheetDisclosure`。
5. 重建對照表會對照舊表輸出 `added` / `removed` / `recategorized`，有差異就以
   非零狀態結束，未覆核不得發布。

## 否決方案

- **B／C（連地區或行業一齊做）。** 標籤空間大好幾倍，而且同一張表混咗維度嗰陣
  冇辦法唔猜——把「北美 30%」當成股票或者債券都係編造。喺三桶都未穩陣之前
  加多兩層，等於把編輯風險乘大。
- **用平台 `fundType` 代替。** 嗰個係基金種類（例如「混合資產基金」），唔係
  配置比重，做唔到「股票佔幾多」。
- **未認得的標籤靜默丟入「其他」。** 會製造假的現金比重——一個睇落好合理、
  但實際係編造的數字。所以認唔到就報錯。

## 後果

- 比較組別平均（`comparison_group_stats`）的資產配置只有三桶；未以資產類別
  披露的基金唔計入，唔可以為咗湊樣本而把行業或地區百分比當成股票。
- 每次重建對照表都要人手覆核差異，係有意的摩擦。
- 地區／行業比較要另開票，並且要先解決「同一張表混維度」呢個問題。

## 重審條件

- 使用者明確要求地區或行業維度的比較。
- 標籤覆蓋率同一致性足以支撐第二層（即係大部分計劃的地區標籤可以對得齊）。
