# ADR 0006 — 基金概覽過期按財政年結日及法定發布期限計算

日期：2026-09-11
狀態：已接受（#192）

## 背景

規格第 97 行要求持倉、資產配置、風險及 FER 按每個計劃的財政年結日及適用的
基金概覽發布期限計算過期。PR #188 當時用咗一個同月度更新週期睇齊的 45 日
權宜值，即係全部計劃同一條線。

但各計劃的財政年結日唔同（平台只列月日，例如 `30 Nov`）。同一日，一個 11 月
年結的計劃可能仲喺發布期限之內，一個 3 月年結的已經過期。用同一個 45 日，
兩邊都會報錯狀態。

## 決定

**逐個基金類別按自己的財政年結日計算寬限日數。**

1. `platform-parser.ts` 抽 `Financial Period End Date` 存做
   `financialPeriodEndDate: "11-30"`（只有月日）。冇呢個欄位或官方寫 `n.a.`
   就走 `unavailableFields`，不可假設。
2. 依《強積金投資基金披露守則》D3.1–D3.4：受託人每個財政期發兩份基金便覽——
   「截至財政期終結日」嗰份連同週年權益報表喺終結後**三個月**內發出，
   「截至終結後六個月」嗰份喺該匯報日起**兩個月**內分發。
3. `data-freshness.ts` 的 `fundOverviewGraceDaysFor()` 揀返資料截至日之前最近
   一份便覽的匯報日，套用對應的法定期限，加規格寫的 30 日寬限，摺埋做逐個
   基金類別自己的寬限日數。
4. 冇財政年結日就退回保守的 45 日（`FUND_OVERVIEW_FALLBACK_GRACE_DAYS`）。
5. 寬限日數喺 `build-staging-seed.ts` 逐個基金類別計好，寫入
   `provenance.freshnessPolicy.fundOverviewGraceDays`（連同
   `fundOverviewPolicyVersion`），**發布之後凍結**。

## 否決方案

- **維持全部 45 日。** 忽略計劃之間的實際差異，兩邊方向都會報錯狀態。
- **由 API 即場計。** 規則常數日後改變就會回溯改寫已發布快照的過期狀態，
  等於事後改寫一個已經公開過的判斷。所以改為喺 seed 時凍結。
- **由資料截至日倒推發布日。** 平台唔提供實際便覽發布日期，倒推等於編造。

## 後果

- 每個基金類別各自帶一份 `freshnessPolicy`。`/rankings?metric=fee|risk` 要逐個
  基金類別讀自己嗰份，**唔可以攞第一隻基金的政策代表全部**——呢個曾經係 bug，
  已經喺 #192 一併修正並釘測試。
- 規則常數之後改變只影響新批次，不會回溯改寫已發布快照。
- 同一日不同計劃有不同過期狀態，係預期行為，唔係 bug。

## 重審條件

- 《強積金投資基金披露守則》修訂發布期限。
- 官方平台開始提供每份基金概覽的實際發布日期——嗰陣就唔使再由財政年結日推。
