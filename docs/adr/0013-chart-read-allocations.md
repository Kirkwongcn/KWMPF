# ADR 0013 — 圖表式配置：讀圖上印出的數字，兩次讀取一致先用

日期：2026-10-04
狀態：已接受（使用者選方案 B）

## 背景

永明彩虹、宏利環球精選、我的強積金三個計劃共 65 隻成分基金的資產配置只以圖表披露：
永明的圖例同百分比、宏利的條形圖都係嵌入圖像，文字層一個字都冇；我的強積金的標註係
文字，但圓餅圖左右兩邊同一條基線，配對唔到。之前一律走 `chart-only`，網站講「官方以
圖表披露」。

使用者要求一頁睇晒基金資料，揀咗方案 B：把圖表轉成圖像再讀取數字，只接受合計 100%、
圖例對得上、兩次讀取結果一致嘅數據，並標明「由官方圖表讀取」。

## 決定

**讀圖上印出的字，唔量圖形。** 數值一定係圖上印住的百分比，唔會由柱長、扇形角度或者
像素面積推算（紅線 1）。

1. `coverage:chart-allocations`（`build-chart-allocations.ts`）按契約 `allocation.chartRead`
   搵配置標題、裁出圖表（宏利按嵌入圖像的位置），300 dpi 渲染。
2. 兩次讀取（`scripts/ocr-chart-region.py`）：RapidOCR 讀全圖；第二次係 Tesseract 另讀
   數值欄（永明、宏利），或者便覽本身的文字層（我的強積金）。Tesseract 的前處理參數一次
   過揀定，唔可以逐張試到同 RapidOCR 一致為止。
3. 全部成立先接受（`fact-sheet-chart-read.ts`）：
   - 兩次讀取的數值個數一樣、由上至下逐個字元一樣；
   - 每行圖例的英文部分同契約內經人手逐張對圖的圖例清單其中一項一字不差（大細楷照
     原文）；英文一樣、中文唔同的按中文分，分唔到就拒絕；同一張圖唔重覆；
   - 每個數值都有圖例；合計喺 100 ± 0.5。
   任何一項唔成立，成張圖照舊 `chart-only`，唔出局部配置（紅線 3）。
4. 結果寫入來源批次的 `fund-fact-sheet-chart-allocations.json`（逐隻基金記頁碼、裁圖範圍、
   印出原樣、兩次讀取用乜、拒絕原因），覆核後由 `coverage:fact-sheet-allocation-report
   --chart-allocations` 合併。合併只填 `chart-only`，而且便覽檔 SHA-256 要同讀圖時一樣。
5. 披露帶 `allocationSource: { method: "chart-read", … }`，每項帶 `printed`（圖上原樣，保留
   尾隨的 0）。網站標明「由官方圖表讀取」、兩次讀取點樣核對、合計（本站計算），並請讀者
   以官方便覽為準。

圖例顯示用清單原文，唔用辨識結果：兩套程式讀繁體中文都唔可靠（「債」讀成「债」、漏字）。
清單係人手對圖抄錄，屬原文照錄，唔係本站改寫。

## 否決方案

- **量扇形角度或柱長。** 得出嘅係估算值，唔係官方數字，而且四捨五入對唔返。
- **只用一套辨識程式。** 2026-06-30 便覽實測 Tesseract 會把「4.7%」讀成「47%」、5 同 9 互換，
  RapidOCR 會把註腳「7」黐落「1.99%」變「71.99%」；單靠一套，錯咗都唔知。
- **圖例做模糊比對。** 同紅線 4 一樣，唔做；辨識程式拼錯（「Utilies」）就拒絕成張圖。

## 後果

- 2026-10-04 批次：65 隻之中 56 隻讀到並核對通過（永明 15／19、宏利 26／29、我的強積金 15／17）；
  9 隻兩次讀取唔一致或者圖例對唔上，照舊「官方以圖表披露」。重跑兩次輸出一字不差。
- 讀圖要 `pdftoppm`、`tesseract`（chi_tra）同 Python `rapidocr-onnxruntime`
  （`requirements-chart-read.txt`），只喺產生來源批次時跑；發布流程只讀已覆核的 JSON。
- 便覽換版、改圖例用字，或者換辨識程式版本，要重新對圖更新清單，再重跑同重新覆核。

## 重審條件

- 受託人改為以文字披露配置（就唔使讀圖）。
- 出現兩次讀取一致但同原文唔同的個案——即係兩套程式會犯同一個錯，要加第三次讀取或者停用。
