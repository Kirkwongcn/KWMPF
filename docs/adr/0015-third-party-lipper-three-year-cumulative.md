# ADR 0015 — 受託人冇提供時，用 HKIFA 轉載嘅 Lipper 三年累積回報（第三方，標明）

日期：2026-10-13
狀態：已接受（使用者 2026-10-13 揀選「Use it, labelled third-party」）

## 背景

ADR 0014 只收受託人官方三年累積回報。2026-10-13 逐個計劃再查（`docs/reviews/2026-10-13-three-year-source-survey.md`）之後，AMTD、交通銀行、東亞三個計劃、中國人壽、我的強積金、宏利退休精選等仍然冇受託人每月三年數字。

香港投資基金公會（HKIFA）每月轉載 Lipper 嘅《MPF Performance Table》（`https://hkifa.org.hk/data/mpf/orso/english/HKMPF_English_MMYYYY.pdf`）。表入面有全部強積金基金嘅 3 個月、1 年、3 年、10 年 % Growth（累積）。萬通受託人每月月報右邊就係轉載呢個表。

量度 2026-08-31 一期：

- 已經有受託人 8 月底三年累積嘅 99 隻基金，98 隻同 Lipper 一樣；唯一唔同係宏利 MPF 利息基金（受託人 2.66、Lipper 2.65）。
- 有 37 行嘅一年數字同積金局平台唔一樣。

所以 Lipper 數字唔可以當受託人數字，但可以喺受託人冇提供時，標明第三方後補位。

## 決定

1. **只補受託人冇嘅基金**：受託人紀錄永遠優先。
   - 第三方唔會取代任何受託人紀錄。
   - 同一批有受託人紀錄嘅基金，唔用第三方。
   - 受託人日後提供同日或較新嘅數字，就取代第三方。
   - 實作：`mergeCumulativeObservations`。
2. **標明第三方**：紀錄帶 `publisher: "hkifa-lipper"`，經 seed、API（`cumulativeReturnSources["3"].publisher`、`cumulativeReturn3yPublisher`）傳到網站。基金頁、比較頁、搵基金表都寫「Lipper（經 HKIFA，第三方）」，唔寫「官方」。
3. **名稱對照表，唔做模糊配對**：Lipper 行名係縮寫（例如「Manulife RC (MPF)-Allianz MPF Core Acc A」），所以用一份逐行、有版本嘅對照表 `data/reference/hkifa-lipper-fund-map.json`，由 `build-hkifa-lipper-map.ts` 產生，人手覆核後提交。一行要同時符合兩個條件先入表：
   - 計劃（寫死嘅前綴表）入面剛好得一個類別，積金局平台同期一年累積回報同 Lipper 一年 % Growth 完全相等；
   - Lipper 基金名每個詞（經寫死嘅縮寫表展開）都喺嗰個類別嘅英文名加類別名入面出現。

   每月建候選只按對照表精確查行名，唔再推斷。
4. **唔借用其他類別**：Lipper 好多計劃只列一個類別（例如宏利退休精選 A 類）。冇列嘅類別記為冇數值，唔借用（紅線 5）。
5. **每月逐行核對**：對照表每一行都要喺表入面剛好出現一次，一年值要同積金局平台同期一年回報完全相等，否則成份作廢（紅線 3）。三年空格（成立未滿三年）唔出紀錄，唔當 0。
6. 其餘同 ADR 0014：
   - 累積唔換算年率化，唔入排名；
   - 每個數值保留自己嘅原文、截至日期、來源網址同 SHA-256；
   - 時效沿用 90 日。
7. 每日工作流程按目標日期下載下一個月份嘅檔（8 月底數據喺 `HKMPF_English_092026.pdf`），表頭日期唔同目標日期就略過。

## 否決過嘅做法

- **唔用（只收受託人）**：缺口會一路留住，直到受託人改變披露方式。使用者揀咗標明第三方後補位。
- **用名稱相似度自動配對**：違反紅線 4，而且 Lipper 縮寫有歧義（「Gr」可以係 Growth 或 Greater）。
- **一個類別嘅數字套落同基金其他類別**：違反紅線 5，類別收費唔同，回報唔同。

## 幾時重審

- 受託人開始提供每月三年數字：受託人優先規則會自動取代，唔使改。
- Lipper 同受託人或者積金局數字出現系統性差異（例如一年核對大量失敗）：停用並重審。
- HKIFA 停止轉載或者更改格式：讀取器會報錯，屆時重審。
