# 香港強積金比較網站：第一版技術方案

研究日期：2026-08-08
狀態：方案草案；部署邊界已確認，未開始實作

## 建議方案

第一版採用「單一網站應用程式 + 獨立資料更新工作流程 + 關聯式資料庫」的結構。網站展示層不直接擷取官方網站；所有可見資料先經原始資料保存、標準化及驗證，再由排名引擎讀取已發布版本。

建議使用：

- 網站：TypeScript、React 及具備伺服器端 API 的現代網頁框架
- 資料庫：Cloudflare D1，保存關聯、版本及查詢索引
- 原始檔案：Cloudflare R2，保存 HTML、PDF、JSON 及擷取紀錄
- 更新工作流程：GitHub Actions 處理擷取及重型解析；Cloudflare Workers Cron 負責觸發、檢查及發布
- 部署：Cloudflare Pages 負責網站，Cloudflare Workers 負責 API；GitHub Public repository 作為唯一程式碼來源

網站框架及具體 Cloudflare 設定在真正建立專案前再決定；目前不應因工具選擇而改變資料邊界。

## 已確認部署決定

- GitHub Public repository 保存程式碼及 GitHub Actions workflow；秘密及正式資源識別碼只保存於受保護的 GitHub environment。
- GitHub Actions 負責擷取、PDF 解析、標準化及交叉核對。
- Cloudflare Pages 發布前端；Cloudflare Workers 提供 API。
- Cloudflare D1 保存標準化資料及排名結果；Cloudflare R2 保存原始文件及版本。
- Workers Cron 負責每日觸發、狀態檢查及切換已驗證發布版本。
- 預設排名每日預先計算；自訂時間框架按查詢即時計算。
- 正常批次自動發布；異常批次先停留待核對，人工核對後才可發布。

## 模組邊界

### Source adapters

每個官方平台、MPFA 文件來源及受託人來源各自有一個 adapter，負責取得原始內容及基本來源資訊。adapter 不負責排名，也不直接修改標準化資料。

### Raw archive

以來源、取得時間及內容指紋保存不可變原始版本。相同內容可以去重，但不可刪除已被使用於展示或驗證的版本。

### Normalizer

將來源欄位映射至資料字典，處理日期、百分比、貨幣、名稱及基金類別。每次映射都要保留原始值和標準化值，不能只保存轉換後結果。

### Validator

執行結構、數值、日期、現行狀態、來源衝突及可比性檢查，產生驗證狀態。驗證失敗的欄位可保留供調查，但不可進入新的公開版本。

### Publication snapshot

把通過驗證的標準化資料及計算結果凍結成一個可發布版本。網站每次請求只讀取目前 snapshot，避免同一頁同時混合不同批次資料。

### Comparison engine

以 `fund_class` 為最小比較單位，按照基金類別／配置、回報及風險分組產生排序。它不產生個人化投資建議，也不把三組指標偷偷合成一個推薦分數。

## 核心資料表

| 資料表 | 用途 |
|---|---|
| schemes | 計劃正式資料及現行狀態 |
| trustees | 受託人資料 |
| constituent_funds | 成分基金與計劃關係 |
| fund_classes | 最小比較單位及類別資料 |
| fund_metrics | 回報、風險、基金規模及資料日期 |
| allocations | 資產、地區及行業分布 |
| holdings | 主要持倉及其截至日期 |
| fee_records | FER、管理費、其他費用及 OCI 的分開紀錄 |
| source_documents | 原始來源、網址、文件日期及擷取資訊 |
| field_provenance | 標準化欄位對應的來源及驗證狀態 |
| publication_snapshots | 已驗證及可展示的版本 |
| update_runs | 每日批次狀態、錯誤及回退紀錄 |

所有有時間性的資料都應使用有效日期及資料截至日期；不要只用資料庫的最後修改時間代替官方資料日期。

## 更新批次設計

批次分成 `collect → parse → normalize → validate → calculate → publish` 六個階段，每階段可獨立重試。任何階段失敗都保留錯誤、來源及批次識別碼；只有 `validate` 和 `calculate` 成功，才可建立新的 publication snapshot。

批次成功條件：

- 主要來源取得完成，或明確記錄不可用來源及其影響範圍
- 沒有未處理的結構或數值異常
- 現行基金狀態已完成三方核對
- 所有公開數值均有來源及資料截至日期
- 排名結果能追溯至同一個 snapshot

批次失敗時，網站繼續使用上一個已驗證 snapshot；介面顯示該 snapshot 的資料日期，而不是顯示空白或推算值。

部分來源失敗時可以建立新快照：未受影響資料照常更新；受影響欄位只能沿用上一個已驗證值，並保留其原截至日期及 `stale` 狀態。沿用欄位不得被當作新資料，也不得在過期後參與相關指標排名。

以下任何情況均把候選批次轉入人工核對：

- 基金新增、移除或身份關係改變
- 同一截至日期的已驗證數值被修訂
- 單月回報絕對值超過 30%
- 資產配置合計不在 99% 至 101% 之間
- 任何費率改變
- 任何主要來源連續兩次取得失敗

異常門檻應配置化並保留變更紀錄；日後只可按實際誤報及漏報證據調整。

## API 及頁面範圍

第一版只需三組公開查詢能力：

1. 基金篩選及分組排名：基金類別、配置、時間框架、風險及資料狀態。
2. 計劃比較：計劃基本資料、旗下基金數量及基金類別分布。
3. 基金詳情：基金類別、配置、回報、風險、費用、持倉、來源及限制。

搜尋、排序及自訂期間應只改變查詢條件，不改變資料版本。第一版不建立登入、觀察清單、交易、個人化推薦或 HR 報告匯出。

## 排名引擎邊界

- 預設提供 1 年、3 年、5 年及 10 年；自訂期間只在有足夠原始歷史資料時可用。
- 基金類別及資產配置先用於建立公平的比較組別，不作跨類別加權分數。
- 基金在同一比較組別內分別按長期回報及風險產生指標排名，不設綜合總分或推薦分數。
- 每項排名顯示比較組別、排序指標、計算方法及資料日期。
- `insufficient`、`pending_verification`、`source_conflict` 及不具可比性的資料不參與排名。
- 過期資料可顯示最近已驗證數值及截至日期，但不參與相關指標排名。
- 同一指標數值相同時並列，後續名次按實際位置跳號，例如第 1、第 1、第 3；不得用基金名稱或其他未披露指標打破同分。
- 自訂期間只接受完整月份且最短為 12 個月；只有具備相同起訖月份完整數據的基金才可互相比較。自訂期間使用扣除基金層面費用後的單位價格作點對點累積回報計算，只展示累積回報並按此排序，不作年化。
- 自訂回報缺少相同起訖月價格時不得插值或排名；三年風險序列缺少任何月份時亦不得插值或排名。
- 回報及風險百分比統一顯示至小數點後兩位，並以相同顯示精度判定並列，避免畫面數值相同但名次不同。
- 風險視圖預設由低波幅至高波幅排列，名稱固定為「較低波幅排序」，並容許反向排序；不得稱為「最佳風險排名」。
- 缺失值及資料日期差異必須有固定規則並寫入測試案例。

## 保存及人工核對原則

- 所有曾支援公開發布快照的原始文件及來源版本在 R2 長期保留，不因後續更新覆寫或刪除。
- 未發布候選批次保留 90 日；失敗擷取內容保留 30 日；已進入人工調查的資料暫停自動刪除。清理不得破壞任何公開快照的來源鏈。
- D1 長期保留發布快照、批次狀態、來源關係及稽核紀錄。
- 第一版不建立獨立管理網站。異常批次由 GitHub Actions 產生核對報告及 artifact，經 GitHub production environment 的 required reviewer 批准後才發布。
- 批准人只能批准或拒絕完整候選批次，不能繞過驗證步驟或直接修改正式 D1 資料。

## 災難復原

- 使用 D1 Time Travel 作短期時間點復原。
- 每週完整匯出 D1 至獨立的 R2 備份位置，每份保留一年。
- 每季在非正式環境執行一次實際還原測試，記錄結果及修復事項。
- 所有被公開快照引用的 R2 原始文件及 manifest 禁止自動刪除；自動清理只適用於未被引用的候選或失敗資料。

## 資料過期期限

- 月度回報及基金規模在相關月結後 45 日仍未取得新一輪已驗證資料，轉為 `stale`。
- 基金概覽所載持倉、資產配置、風險及 FER，在適用法定發布期限後 30 日仍未取得已驗證資料，轉為 `stale`；期限按每個計劃的財政年結日分別計算。
- 現行基金狀態每日核實；連續 7 日未能成功完成核實時，相關基金暫停排名並進入人工核對。

## 安全及可靠性

- 更新工作流程使用最小權限的來源憑證；網站唯讀存取已發布資料。
- 原始文件及來源網址當作不可信輸入，解析時限制檔案大小、格式及執行時間。
- 對外頁面不顯示內部錯誤、憑證或原始擷取細節中的敏感資訊。
- 每次發布保留版本及回退指標，並記錄誰或哪個工作流程觸發發布。
- 監察來源失敗率、基金數量變化、待核實數量及最後成功更新時間。
